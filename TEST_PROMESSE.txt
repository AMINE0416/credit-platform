TEST DE L'AFFICHAGE DES PROMESSES DE PAIEMENT
═══════════════════════════════════════════════════════════════════

J'ai ajouté des logs détaillés pour diagnostiquer pourquoi les promesses 
ne s'affichent pas. Voici comment tester:

ÉTAPE 1: PRÉPARER UN DOSSIER DE TEST
─────────────────────────────────────────────────────────────────────
1. Connectez-vous en tant qu'AGENT (agent@eqdom.ma / password123)
2. Ouvrez un dossier avec statut EN_COURS ou NOUVEAU
3. Ajoutez une action avec:
   - Nouveau statut: PROMESSE
   - Nature action: APPEL_SORTANT (ou autre)
   - Motif impayé: DIFFICULTE_FINANCIERE_TEMPORAIRE
   - Compte rendu: "Client promet de payer"
   - Code résultat: RPC
   - Montant promesse: 5000 (par exemple)
   - Date promesse: Choisir une date (par exemple demain)
4. Enregistrer

ÉTAPE 2: FAIRE UNE TRANSITION VERS SUIVI_PROMESSE
─────────────────────────────────────────────────────────────────────
5. Sur le même dossier, ajoutez une nouvelle action:
   - Nouveau statut: SUIVI_PROMESSE
   - Nature action: APPEL_SORTANT
   - Compte rendu: "Suivi de la promesse"
   - Code résultat: RC
6. Enregistrer

ÉTAPE 3: VÉRIFIER L'AFFICHAGE
─────────────────────────────────────────────────────────────────────
7. Rechargez la page du dossier (Ctrl+F5)
8. Vous devriez voir un encadré violet avec:
   📅 Promesse de paiement en cours
   Montant: 5,000 MAD
   Date promise: [la date que vous avez choisie]
   Note: "Client promet de payer"

ÉTAPE 4: VÉRIFIER LES LOGS
─────────────────────────────────────────────────────────────────────
9. Ouvrez la console du navigateur (F12)
10. Regardez les logs qui commencent par:
    - "=== PROMESSE useEffect ==="
    - "[getDernierePromesse]"
    
11. Regardez aussi les logs du backend qui commencent par:
    - "=== GET /api/dossiers/X/derniere-promesse ==="
    - "=== DossierService.getDernierePromesse(X) ==="

DIAGNOSTIC DES PROBLÈMES POSSIBLES:
─────────────────────────────────────────────────────────────────────

Cas 1: L'encadré ne s'affiche pas
→ Regardez les logs de la console
→ Vérifiez que le statut du dossier est bien "SUIVI_PROMESSE"
→ Vérifiez que l'API retourne bien des données (Status 200)

Cas 2: API retourne 204 (No Content)
→ Cela signifie qu'aucune action avec promesse n'existe
→ Vérifiez que vous avez bien créé une action avec montant ET date de promesse
→ Les deux champs doivent être remplis

Cas 3: Erreur 401 Unauthorized
→ Le token JWT a expiré, reconnectez-vous

Cas 4: Le dossier n'est pas en SUIVI_PROMESSE
→ L'encadré ne peut s'afficher que si le statut actuel est SUIVI_PROMESSE
→ Faites la transition comme décrit ci-dessus

RÉSUMÉ:
─────────────────────────────────────────────────────────────────────
L'affichage nécessite:
1. Un dossier avec statut actuel = SUIVI_PROMESSE
2. Au moins une action dans l'historique avec:
   - montant_promesse rempli (NOT NULL)
   - date_promesse remplie (NOT NULL)
3. L'encadré affiche la DERNIÈRE action qui contient ces deux valeurs

Si ça ne fonctionne pas, envoyez-moi:
- Les logs de la console navigateur
- Les logs du backend
- Le numéro du dossier testé
